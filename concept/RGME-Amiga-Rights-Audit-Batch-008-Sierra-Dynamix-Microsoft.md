# RGME Amiga Library Rights Audit — Batch 008
## Sierra On-Line / Dynamix → Activision Blizzard → Microsoft

**Date:** 2026-10-28  
**Status:** Evidence-backed family audit; not legal advice.

## Executive summary

Batch 008 combines two highly useful RGME patterns.

First, Sierra has a long but comparatively traceable corporate succession. Sierra On-Line passed through CUC/Cendant and Havas/Vivendi structures, later becoming part of Activision's catalogue. Activision and Vivendi Games combined into Activision Blizzard, and Microsoft completed its acquisition of Activision Blizzard in October 2023.

For RGME this creates a strong **corporate licensing route**.

It does not mean:

```text
Microsoft
   =
direct copyright owner of every byte,
asset, trademark and contract associated
with every Sierra Amiga release
```

The Rights Graph therefore needs to distinguish **corporate parent**, **IP owner**, **trademark owner**, **publisher**, **distributor** and **licensing contact/steward**.

Second, the Sierra adventure catalogue is a major **engine-aware runtime corpus**. Many AGI/SCI titles are supported by ScummVM. This means the multi-runtime architecture introduced in RGME v0.3 is not a Lucasfilm-specific exception; it is a reusable platform capability.

```text
                User-owned Sierra data
                         |
              +----------+----------+
              |                     |
              v                     v
            PUAE                 ScummVM
       Amiga preservation      AGI / SCI runtime
              |                     |
              +----------+----------+
                         |
                         v
                    RGME Profile
```

## ScummVM as execution strategy

This batch reinforces ADR-021 through ADR-024 from Overall Concept v0.3.

For a supported title:

```yaml
execution:
  strategies:

    - id: amiga-authentic
      type: machine-emulation
      adapter: emulatorjs-puae
      requiresOriginalData: true
      requiresOriginalExecutable: true

    - id: scummvm-modern
      type: engine-runtime
      adapter: scummvm
      requiresOriginalData: true
      requiresOriginalExecutable: false
```

ScummVM support must be verified against the exact release rather than inferred merely from the title.

This proves that execution strategy should be resolved at **release level**, not publisher level.

## Rights-graph improvement — corporate parent vs IP steward

Batch 008 adds an important distinction.

Current schema should support:

```text
Microsoft
    |
    | CORPORATE_PARENT_OF
    v
Activision Blizzard
    |
    | corporate/catalogue lineage
    v
Sierra
    |
    +------ PUBLISHED ------> Game
    |
    +------ MAY_OWN_IP -----> Game
```

A separate property should capture:

```yaml
licensing_route:
  entity: Activision / Microsoft group
  confidence: high

direct_ip_owner:
  entity: unknown_or_title_specific
  confidence: unresolved
```

This is much safer than storing:

```yaml
current_ip_holder: Microsoft
```

for every historical Sierra title.

## Why this matters for licensing

A future RGME business-development workflow should answer two different questions:

1. **Who appears to own the relevant rights?**
2. **Who can actually receive and process a licensing request today?**

Those may be different entities.

This suggests another Rights Intelligence relation:

```text
LICENSING_STEWARD_FOR
```

and a dedicated object:

```ts
interface LicensingRoute {
  gameId: string;
  organizationId: string;
  role:
    | "ip-owner"
    | "corporate-parent"
    | "licensing-agent"
    | "publisher"
    | "unknown-steward";

  contact?: ContactPoint;
  confidence: number;
  evidenceIds: string[];
}
```

## Strategic assessment

### Major Sierra franchises

*King's Quest*, *Space Quest*, *Leisure Suit Larry* and related properties are poor first unlicensed public-demo candidates.

They are excellent:

- BYOG targets;
- ScummVM integration targets;
- multi-runtime demonstrators;
- language/release identity test cases.

### Less active Dynamix/Sierra catalogue

Dormant or lightly exploited titles are more interesting for eventual rights outreach.

A dedicated later pass should score them for:

- current commercial activity;
- trademark activity;
- creator availability;
- chain-of-title clarity;
- fan recognition;
- modernization potential.

## RGME architectural conclusion

After Lucasfilm and Sierra, **engine-aware execution is no longer optional conceptually**.

We now have at least two substantial families where:

```text
Original Game Data
        |
        +--> Original Machine Runtime
        |
        +--> Open Engine Runtime
```

is a natural model.

Therefore the ScummVM adapter should remain outside the strict PUAE MVP release gate, but it should become the **first official v0.3 runtime expansion**, not merely an experiment.

## Batch conclusion

Batch 008 establishes four useful patterns:

1. long corporate succession;
2. corporate parent versus direct IP owner;
3. licensing steward versus legal owner;
4. reusable engine-aware execution across multiple publishers.

The last point is strategically important: the v0.3 multi-runtime architecture is now validated by more than one catalogue.
